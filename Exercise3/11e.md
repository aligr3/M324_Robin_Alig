## 1. What does my website do and why is it relevant for me?

My website is a small "Git Survival Kit". It has a commit message generator that shows a random funny
(and too honest) commit message, and a short cheat sheet with the most important Git commands.
It's relevant for me because I use Git every day as an IT apprentice, and in M324 we learn the workflow
`pull -> add -> commit -> push`. The site also shows a real deployment pipeline: every release is
published automatically with GitHub Actions.

## 2. Let's assume the app needs a database. How could you do that?

GitHub Pages only hosts static files (HTML, CSS, JavaScript). It can't run server code or a database.
Some options:

- **Backend-as-a-Service:** Use a hosted database with a JavaScript API, for example Firebase/Firestore or
  Supabase. The static website talks to it directly from the browser. Access is controlled with
  authentication and database rules. Never put secret keys in the frontend.
- **Separate backend:** Build a small API (for example Node.js/Express) with a database like PostgreSQL
  or MongoDB and host it on a service like Render, Railway or Azure. The website on GitHub Pages calls the API.
- **Browser storage:** For data that only one user needs, `localStorage` or IndexedDB in the browser is
  enough. There is no server, but the data isn't shared and stays on that device.

## 3. Deploy only when a new tag is pushed

Yes, this is possible. I changed the GitHub Pages source from "Deploy from a branch" to "GitHub Actions"
(Settings -> Pages -> Source). Then I created my own workflow in `.github/workflows/pages.yml`:

```yaml
on:
  push:
    tags:
      - "v*"
  workflow_dispatch:
```

The workflow runs only when a tag starting with `v` is pushed (for example `v1.0.0`), not on normal commits to
`main`. `workflow_dispatch` also lets me start it manually. The workflow checks out the code, uploads
the `Exercise3` folder as a Pages artifact (`actions/upload-pages-artifact`) and deploys it (`actions/deploy-pages`).
The workflow file must be in `.github/workflows/` at the repository root, otherwise GitHub does not find it.

Creating a release on GitHub with a new tag also creates the tag, so publishing a release deploys a new version.
From the command line:

```bash
git tag v1.0.1
git push origin v1.0.1
```

Note: The `github-pages` environment has protection rules that may only allow deployments from `main`.
In that case, add a rule for tags `v*` under Settings -> Environments -> github-pages.
